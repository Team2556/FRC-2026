🔧 Trigger Normalisation Snippet

PS triggers return -1.0 when released and +1.0 when fully pressed. If your code expects a 0 → 1 range (like Xbox), normalise it: 

def normalize_ps_trigger(raw):
    """Convert PS -1..+1 → 0..1"""
    return (raw + 1.0) / 2.0

# Example usage:
r2 = controller.getR2Axis()   # -1.0 to +1.0
r2_norm = normalize_ps_trigger(r2)  # 0.0 to 1.0

# Or just check if pressed past halfway:
if r2 > 0.0:   # equivalent to Xbox > 0.5
    ...shoot()

# whileTrue trigger binding:
controller.R2()  # works directly — no normalise needed

⚠ Important Gotchas

Trigger range is -1 → +1 Unlike Xbox (0 → 1), PS triggers start at -1.0 when fully released. A check like getR2Axis() > 0.5 would only fire when the trigger is 75% pressed. Use getR2Axis() > 0.0 as the midpoint, or normalise with (raw + 1) / 2.
Stick Y still inverted Same as Xbox — getLeftY() returns -1.0 when pushed forward/up. Always negate: velocity_x = -controller.getLeftY().
Button numbers differ from Xbox Cross = btn 2, Circle = btn 3, Square = btn 1, Triangle = btn 4. Use named methods (getCrossButton()) not raw numbers to avoid confusion.
Right stick Y = axis 4 PS4 right stick Y is on raw axis 4, not axis 3 like Xbox right X. The right stick X is axis 3, Y is axis 4. The triggers occupy axes 2 and 5. This raw-axis order is: LeftX(0), LeftY(1), L2(2), RightX(3), RightY(4), R2(5).
